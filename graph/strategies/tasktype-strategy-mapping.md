# G1 TaskType → mother Strategy mapping

Status: **normative draft**

This document maps high-frequency authentic TaskTypes to a small reusable Strategy set.

The mapping is **recommended procedure**, not a hard prerequisite. Concrete Question tagging remains authoritative.

Legend:

- `P` = primary mother strategy normally worth teaching/triggering;
- `S` = common secondary/composed strategy;
- `—` = no default mother strategy; rely on Knowledge/Ability directly.

## 6. No one-TaskType-one-Strategy rule

Examples of rejected proliferation:

```text
“人物形象五步法”
“标题作用五步法”
“段落作用五步法”
“古诗情感五步法”
```

when they are only surface variants of existing mother strategies.

Task-specific differences remain in:

- recognition signals;
- Knowledge prerequisites;
- Ability nodes;
- output skeleton;
- evidence standards;
- boundary conditions.

Strategy stays reusable.

## 7. Same Strategy across different TaskTypes

### S1 evidence→explanation→conclusion

appears in:

```text
现代人物判断
文言人物判断
诗歌情感判断
文体判断

```

The text representation changes; the core reasoning procedure does not.

### S2 comparison

appears in:

```text
两篇现代文
两则文言
两首诗
观点材料
人物对比
```

This is exactly the transfer ChineseTutor should make visible in the Learner Profile.

## 8. Mapping implementation rule

Canonical TaskType records may store:

```yaml
recommended_strategy_node_ids:
  - CN-S-...
```

Concrete Question records should normally target the underlying Ability/Knowledge nodes; Strategy is included as a target only when the training purpose explicitly observes strategy execution/automation.

Do not infer Strategy mastery simply because a Question belongs to a TaskType that recommends it.
